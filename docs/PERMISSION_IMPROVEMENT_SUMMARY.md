## 核心改进

### 权限扩展

**原有设计**:
- 教师只能查看/管理**自己创建**的学生账号

**改进后**:
- 教师可以查看/管理**自己创建的学生** ✅
- 教师可以查看/管理**加入自己班级的学生** ✅ (新增)

### 支持的关系类型

#### 1. 创建者关系 (Creator Relationship)
```
教师A 通过批量导入创建 → 学生S
数据库: users.creator_id = teacher_a.id
权限: 永久有效，不受班级变动影响
```

#### 2. 班级关系 (Class Membership Relationship)
```
教师B 创建班级C → 添加学生S到班级C
数据库: class_memberships + collections (is_class=true)
权限: 动态关系，可添加/移除
```

#### 3. 组合场景（最常见）
```
教师A创建学生S                    → 创建者权限
教师A创建班级C1，添加学生S        → 班级权限
教师B创建班级C2，添加学生S        → 班级权限

结果：教师A和教师B都可以查看/管理学生S
```

## 技术实现

### SQL查询

检查教师是否为学生的班级教师：

```sql
SELECT EXISTS (
    SELECT 1 
    FROM class_memberships cm
    JOIN collections c ON cm.class_id = c.id
    WHERE cm.student_id = ?              -- 学生ID
      AND c.creator_id = ?               -- 教师ID
      AND c.is_class = true              -- 确保是班级
      AND cm.deleted_at IS NULL          -- 未被移除
) AS is_class_teacher;
```

**性能优化**:
- 使用 `EXISTS` 而非 `COUNT(*)`（找到第一条即返回）
- 利用现有索引：
  - `class_memberships_student_id_idx`
  - `collections_creator_id_idx`
  - `collections_is_class_idx`

### 权限缓存

**策略**: 请求级缓存，自动版本管理

**缓存键**:
```
perm:{viewer_id}:{viewer_updated_at}:{target_id}:{target_updated_at}:{permission}
```

**失效机制**:
```sql
-- 角色变更时自动失效
UPDATE users SET role = 'moderator', updated_at = now() WHERE id = 123;
-- updated_at 改变 → 缓存键改变 → 旧缓存失效
```

**性能提升**: 约80%减少重复数据库查询

## 使用场景

### 场景1: 学校内部管理

```
张老师（数学老师）:
  - 批量导入30个学生账号
  - 创建"数学1班"
  - 将30个学生加入数学1班
  
权限: 张老师可以查看和管理这30个学生（创建者关系）
```

### 场景2: 跨班级协作

```
张老师（数学老师）创建学生小明
李老师（英语老师）创建"英语1班"，将小明加入

权限:
  - 张老师可以管理小明（创建者关系）
  - 李老师可以管理小明（班级关系）
  - 两位老师都可以查看小明的作业完成情况
```

### 场景3: 学生转班

```
小明从"英语1班"转出（软删除 class_membership）

权限变化:
  - 张老师仍可管理小明（创建者关系不变）
  - 李老师失去对小明的管理权限（班级关系断开）
```

## 安全保障

### 1. 软删除保护

```sql
-- 只检查未删除的班级成员
WHERE cm.deleted_at IS NULL
```

**作用**: 学生从班级移除后，教师立即失去权限

### 2. 班级类型验证

```sql
-- 只检查标记为班级的 collection
WHERE c.is_class = true
```

**作用**: 防止通过普通作品集绕过权限

### 3. 请求级缓存

**特性**:
- 缓存存储在 `ngx.ctx`（请求结束自动清理）
- 版本化缓存键（角色变更自动失效）
- 无全局污染风险

### 4. 审计日志

**记录内容**:
- 操作者（ID、用户名、角色）
- 目标（ID、用户名）
- 变更内容（旧值、新值）
- 时间、IP、User-Agent

**存储**:
- 文件日志（nginx error.log）
- 数据库（audit_logs表）
